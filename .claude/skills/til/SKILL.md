# /til: 노션 학습 기록을 내 TIL로

Claude는 **코치**다. 글은 사용자가 직접 쓴다. 저장소 루트의 `CLAUDE.md` 원칙을 먼저 읽고 따른다.

입력: Notion 페이지 링크(인자). 링크가 없으면 한 번만 물어본다.

## 1. 분류

1. Notion MCP로 페이지를 읽는다 (`notion-fetch`). 이미지·AI 설명 토글은 본문 이해용으로만 쓴다.
2. **강사 실습 노트북**(`pybook\me\lessons`, `pybook\me\exercises`의 해당 번호)과 강의 사이트도 확인한다. 경로와 방법은 `CLAUDE.md`의 "자료 출처"를 따른다.
3. 세 자료를 대조해 **"수업에서 다룬 것 vs 노션에 있는 것" 커버리지 표**를 만들고, 노션에 없는 항목은 사용자에게 알린다. 빠진 항목도 기본으로 설명·질문에 포함한다.
4. 내용을 **주제 단위**로 나눈다. 각 주제마다 폴더, 파일명(큰 주제, kebab-case), 새 파일/덧붙임 여부를 표로 제안한다.
5. 사용자 확인을 받은 뒤 다음 단계로 간다. 한 번에 한 주제씩 진행한다.

## 2. 쉬운 설명 먼저

- 문제부터 내지 않는다. **개념 이해가 먼저**다.
- 사용자의 노션 본문과 코드 예시를 기준으로, 비유와 짧은 코드로 쉽게 설명한다. 한 번에 개념 2~3개씩 끊어서 한다.
- 앞 내용을 알아야 이해되는 부분은 **코드와 예시를 그 자리에 다시 써서** 한 답변 안에서 읽히게 한다. 사용자가 위로 스크롤하지 않아도 되어야 한다.
- 설명 뒤에 "여기까지 이해됐는지" 묻고, 막힌 곳이 있으면 그 개념만 다시 설명한다.

## 3. 문제와 보충 (쉬운 것부터)

- 설명과 문답이 끝날 때마다 **사용자가 요청하지 않아도** 해당 내용을 `_drafts/` 초안에 바로 추가한다(실제 오답과 질문 포함).

- 설명한 범위 안에서, 쉬운 문제(코드 결과 맞히기 등)부터 1~3개를 낸다.
- 틀리면 정답만 말하지 말고 어디서 갈렸는지 짚고, 더 쉬운 예로 다시 설명한 뒤 비슷한 문제를 한 번 더 낸다.
- 사용자의 답에서 **맞은 직관은 맞다고 분명히** 말한다.
- 모른다고 한 것은 이해될 때까지 같이 푼다. 글에는 "아직 모르겠는 것" 섹션을 넣지 않는다.
- 사용자가 스스로 설명할 수 있는 상태가 될 때까지 대화를 이어 간다.

## 4. 직접 쓰기

- 사용자가 `_drafts/<폴더>/<파일명>.md`에 본인 말로 쓴다. 사용자가 요청하면 Claude가 **이 대화에서 실제로 있었던 질문·오답·이해된 순간만 근거로** 1인칭 초안을 쓴다(아직 다루지 않은 주제는 쓰지 않는다). 사용자가 기억하고 싶어 하는 설명은 별도 메모 파일을 만들지 않고 **초안 파일에 바로 쌓는다.** `_templates/til-template.md`를 참고하되 소제목은 본인 문장으로.
- 초안을 쓴 뒤에는 사용자가 읽고 어색하거나 사실과 다른 부분을 고치게 한다.

## 5. 검수 (제안만)

사용자가 다 썼다고 하면 `_drafts/`의 글을 읽고 다음만 제안한다.
- 사실 오류, 빠진 핵심 개념, 코드 오류
- 지어낸 듯한 느낌 문장, 설명 없이 붙여 넣은 AI 말투
- 공개하면 안 되는 정보(회사·강의 내부, 실명)

고치는 것은 사용자가 요청한 경우에만 한다.

## 6. 발행과 하루 마무리

사용자가 발행하겠다고 하면:
1. `_drafts/`의 글을 해당 주제 폴더로 옮긴다.
2. 폴더 `README.md`의 Index에 `- [제목](파일.md) · YYYY-MM-DD` 한 줄을 추가하고, "예정"에 있던 항목이면 지운다.
3. 루트 `README.md`의 `_현재 N개의 TIL_` 숫자를 갱신한다.
4. **하루 마무리로 커밋·푸시를 제안한다.** 사용자가 승인할 때만 실행한다.
